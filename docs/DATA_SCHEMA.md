# 数据与导入合同 v1.0.0

主库使用 SQLite，`user_version=1`。每个实体按行保存，包含稳定 ID、修订号、创建/修改 UTC 时间、软归档标志及结构化字段 JSON；不是单一全库 JSON。原文以原始字节保存在来源快照中，区段和引用由业务层校验。

| 表                         | 内容                                                   |
| -------------------------- | ------------------------------------------------------ |
| sources                    | 原文件名、来源种类、权限、讲者与真实日期（可空）       |
| versions                   | 来源 ID、SHA-256、快照相对路径、导入时间；版本不可变   |
| blocks                     | 固定版本、原始顺序、标题路径、原文和行范围；区段不可变 |
| courses / topics           | 课程元数据、来源版本、主题父子层级、顺序与讲义块       |
| cards / cases              | 知识资料层、原名类型别名、来源及案例身份和关联         |
| notes / reviews            | 原始输入、可选发生时间、后续事件关系；复盘独立存储     |
| relations                  | 两端 ID、关系类型、理由、引用和审核状态                |
| learning                   | 对象的用户学习状态与阅读位置，不随资料导入覆盖         |
| drafts / revisions / audit | 草稿批次、对象历史修订、操作者与请求审计               |
| requests                   | 请求 ID、内容摘要和原结果，用于相同请求幂等重试        |
| settings / import_previews | 本地权限、导入预览元数据与清理状态                     |

运行时上下文和导入原始字节存于受控文件目录，不写入 `import_previews` 的 SQLite JSON。上下文仅在显式选择时进入备份；凭据不会被备份。

所有来源引用最终都必须解析到有效的 `source_document_id`、`source_version_id`、`source_block_id`，且实体关系一致。课程 coverage 为本次来源版本中每个区段标明去向。来源可定位与讲义语义忠实是两项不同检查，后者仍需人工核对。

机器可读写入 schema 位于 `schemas/*.json`，由共享 Zod 输入合同导出；MCP 与 HTTP 对同一工具输入使用相同严格合同。逐工具行为见 `API_CONTRACT.md`。知识卡更新使用 `expected_revision`，个人学习层存于独立表，不接受资料包覆盖 `notes` 或 `learning`。

## 导入

Markdown/TXT 以 UTF-8 原样保存，并按确定性规则生成来源区段与原文目录。识别到明确的“直播日期：YYYY年M月D日”时才记录来源日期；未注明则留空，不用导入时间代替。

JSON 支持 `course_draft`、`knowledge_draft` 和 `manifest.json`。资料包 schema 版本为 `1.0.0`，形状如下：

```json
{
  "schema_version": "1.0.0",
  "kind": "learning_workbench_import",
  "sources": [
    {
      "path": "sources/example.md",
      "source_document_id": "tmp_document_1",
      "source_version_id": "tmp_version_1",
      "blocks": [{ "id": "tmp_block_1", "order": 0 }]
    }
  ],
  "courses": [],
  "knowledge": [],
  "cases": []
}
```

包内来源、主题与区段可使用临时 ID，不要求调用者事先从数据库领取正式 ID。课程讲义引用与 coverage 可以指向清单中的临时 ID。临时来源通过清单的精确文件路径映射到本次导入产生的来源和版本；区段按显式 `order` 或清单区段顺序映射。也可在引用中提供 `source_path` 与 `block_order`，或唯一 `content_identity`。系统会校验最终映射是否指向真实来源区段；缺失或不唯一时拒绝提交。

临时主题 ID 需带稳定的 `content_identity`。新课程会生成正式主题 ID，并在草稿结果中记录临时到正式 ID 的映射；更新既有课程时，必须用唯一身份匹配现有主题。包内知识卡引用的临时主题 ID 会映射到课程草稿的正式主题 ID，卡片草稿须等课程草稿采纳后才可接受。`preview_import` 会展示来源路径与哈希匹配、临时主题身份及卡片依赖计划；`commit_import` 的结果记录实际映射。预览用于检查映射依据，不证明旧包所有语义字段都正确。

导入过程先把上传原始字节写入受控 staging 文件，SQLite 预览行只保存文件元数据、路径、SHA-256 与解析状态。提交前会校验暂存内容哈希；提交以数据库事务写入来源和草稿，先创建备份。提交成功后清除 staging 并保留可幂等重试的结果；取消、失败和过期预览会删除暂存文件，过期阈值为 24 小时，启动时会清理过期或孤立暂存目录。事务失败时只清理本次新增且不再被正式版本引用的来源文件，不碰已有来源快照。

Markdown、TXT 与 JSON 支持 UTF-8；同哈希来源跳过，内容变化的同名文件产生新来源版本，旧引用仍指向旧文本。未知 JSON 字段或格式会明确报告为不支持，不会静默当成课程导入，也不会猜测 legacy 包的任意字段。资料包不得写入个人笔记或学习状态。

限制：每批最多 1000 个文件，总展开体积 64 MiB，普通文本或 ZIP 成员最多 8 MiB；仅允许 Store/Deflate ZIP，拒绝绝对路径、上级路径、反斜线、链接、加密项和异常长度。PDF/DOCX 会报告不支持；需另行提取成文本后导入。

## 导出

阅读迁移导出包含 `data.json`、逐项 Markdown、原来源快照和说明，保留 ID 与来源关系。它不是第二主库，不支持文件双向编辑。分享模式按用户指定词替换文本并去除原始快照，下载前提供预览。备份包与阅读导出是不同格式，只有备份用于全库恢复。

## 草稿与回退

接受草稿时同时检查草稿修订号、课程修订号和相关主题归属/修订，避免并发更新被覆盖。接受操作处于事务内。撤回仅在正式对象没有后续修订时执行；旧主题可归档但不级联删除个人笔记。个人记录可归档，本版不提供永久删除。
