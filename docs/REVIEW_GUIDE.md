# 代码审查指南

## 审查目标

请审查这个本地优先的学习与复盘工作台，关注数据边界、权限执行、来源可追溯性、恢复安全和常见 Web 安全问题。仓库面向代码审查，附带的课程、知识卡、个人记录、截图及基准输入均为虚构 DEMO，不代表真实用户资料。

请只依据仓库中可见的代码与测试给结论。不要推断或编造未提供的课程内容、用户经历或专门方法结论。发现问题时按严重度标为 P0–P3，并写明文件与行号、触发条件、实际影响、可复现证据和最小修复建议；把确认的缺陷与测试尚未覆盖的风险分开说明。

## 建议入口

- `src/server/`：本机 HTTP、会话、请求来源校验和 MCP API 路由。
- `src/domain/service.ts`、`src/domain/store.ts`：业务权限、数据变更、搜索和引用行为。
- `src/domain/backup.ts`：备份校验、预览与恢复流程。
- `src/mcp/`：stdio 协议适配器及其与本地服务的连接。
- `src/web/`：界面、客户端请求和本地草稿。
- `schemas/`、`prompts/`：外部 Agent 的输入输出约定。
- `tests/`：临时隔离目录中的服务层和安全测试。
- `scripts/`：开发、集成验证与合成数据基准脚本。运行前先检查脚本副作用。

## 重点检查

1. 默认拒绝与服务端授权：读权限和写权限是否分别检查；私人记录是否按明确 ID 授权；拒绝后是否仍可能从搜索、引用、错误消息或关联对象侧漏出内容。
2. 本地 Web 边界：监听地址、Host/Origin、会话 Cookie、CSRF 与 MCP 凭据校验是否覆盖所有敏感路由；客户端提供的身份或确认字段是否被错误当作授权。
3. 导入与来源：JSON 结构校验、重复导入幂等、来源版本固定、段落游标、非法引用拒绝，以及 ZIP 路径穿越、符号链接和体积上限。
4. 草稿审核：覆盖遗漏、修订冲突、拒绝与撤回状态是否可靠；正式接受后，用户个人笔记与学习状态是否保留。
5. 备份恢复：校验清单和哈希、预览隔离、确认门槛、失败回滚，以及恢复后凭据和权限重置是否符合数据边界。
6. 导出与搜索：课程导出是否混入私人记录；繁简转换、别名、短词查询和分页是否造成错误匹配或权限泄漏。
7. 操作范围：程序是否只访问预期本地数据目录；是否意外进行联网请求、模型调用、遥测、外部上传或任意路径读写。

## 可重复验证

在满足 `package.json` 声明的 Node.js 版本并安装锁定依赖后，可运行：

```sh
npm test
npm run build
```

单元与集成测试使用 Node 临时目录和代码生成的 DEMO 文本，不需要导入真实资料。性能脚本也在临时库生成虚构数据，测量范围是本机服务层，不覆盖浏览器、MCP 传输、并发负载或真实资料规模。截图仅展示 DEMO 界面。

启动脚本、MCP 实连脚本和 UI 集成脚本可能启动本机服务或写入演示库。运行前请先阅读具体脚本，确认它使用隔离的 DEMO 数据目录；不要把真实数据库路径传给测试或基准程序。真实 MCP 配置应用脚本会修改本机客户端设置，只能在审查者明确需要验证该行为时检查，不应作为常规 CI 步骤。

## 结论边界

测试通过只证明所列用例在当前环境成功，不能证明未覆盖路径安全，也不等于独立渗透测试、无障碍审计、跨平台验证或多人并发验收。工作台保存的数据和备份没有应用层加密；外部 Agent 客户端接收已授权内容后，内容可能进入该客户端的模型上下文。仓库不提供云端访问本机服务的能力。

提交审查前，请确认版本控制索引中没有本机专属上下文、原始需求、真实来源材料或其派生讲义、导入盘点、凭据、数据库、备份和本机 MCP 配置记录。只审查公开仓库里的通用软件行为与 DEMO。
